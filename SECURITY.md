# Security Policy

## Reporting a vulnerability

Please do not disclose vulnerabilities in a public issue or discussion.

If GitHub's private vulnerability reporting is enabled for this repository, use **Security → Advisories → Report a vulnerability**. If that option is unavailable, contact the maintainer through the contact method listed on the GitHub profile and request a private channel before sharing technical details.

Include the affected version or commit, the relevant component, reproduction steps, and the potential impact. Redact credentials, API keys, private documents, and personal data from all reports.

## Sensitive local data

FidelityFlow may create local extracted-content caches, project-memory databases, session briefs, and optional tool-output archives. These files may contain sensitive project information. They are not encrypted by FidelityFlow; protect them with operating-system permissions and exclude them from public repositories and support bundles.

## Supported versions

Security fixes are prioritized for the latest published release and the current main branch while the project is under active development.
